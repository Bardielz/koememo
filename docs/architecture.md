# 架构

录音是当前唯一实现的业务域。采用三个 Gradle 模块，避免将每个类都拆为模块。

- `recording:domain`：会话状态、配置约束与停止保护规则，不依赖 Android。
- `recording:application`：开始、暂停、结束、恢复和设置用例；定义持久化、控制及播放端口，只依赖 domain。
- `app`：presentation 呈现状态；infrastructure 实现 Android 音频、文件、偏好和服务；bootstrap 组装依赖。

会话允许暂停后继续；结束会清除当前会话引用，不删除文件。Android 服务负责线程、唤醒锁和前台通知，用例负责会话及持久化状态。原组件类保留为兼容入口。录音日志格式、应用 ID 与偏好键保持兼容。

手机伴侣位于 `apps/phone/android`，音频传输协议位于 `packages/contracts/audio`，双端 Android 统计实现在 `packages/android/telemetry`。桌面端保留扩展位置。

## 多品牌 Android 手表适配方案

目标是让满足录音条件的 Android 手表独立完成录音、分段保存和恢复，包括缺少 Google Play 服务的设备。当前手表 APK 的最低版本是 API 30，清单要求手表设备类型和麦克风。厂商系统能否安装 APK、能否在熄屏后持续录音，仍需按设备和固件验证。以下边界用于后续开发。

| 能力 | 实现位置与依赖 | 能力缺失或运行失败时 |
|---|---|---|
| 录音与本地保存 | 沿用 Android 音频、前台服务和存储实现。开始前检查权限、音源和编码配置，实际初始化结果决定能否开始。 | 实验配置不可用时提示可用配置；记录中断时保存已有分段并记录原因。 |
| 手机同步 | 传输用例只处理片段、校验、回执和重试。当前 Google Data Layer 客户端及监听服务属于 Wear OS 传输适配器。未来其他传输方式复用音频协议。 | 缺少服务时显示当前设备不支持此传输方式；暂时断连时保留待同步片段，重连后按回执续传。 |
| 性能诊断 | 双端共享电池和 UID 统计，API 35+ 可按需枚举 PowerMonitor。每条观测标明范围（整机、UID 或线程）、单位和来源。 | 缺失字段省略；空列表表示该接口未暴露计数器。采样失败不得中断录音或传输。 |
| 厂商扩展 | 三星等厂商的 SDK、权限、回调及服务版本检查封装在各自适配器中。将公开且获准分发的接口作为 APK 的依赖；ADB 可见的系统服务如三星 `sdhms` 留在开发诊断工具中。 | 缺少 SDK、服务版本不符、授权被拒或服务退出时，仅停用受影响能力。 |

### 依赖与装配

业务规则留在 `domain`。用例需要跨平台能力时，在对应功能的应用层定义小接口，例如传输或诊断采样；接口只使用项目自己的数据类型。Android、Google 和厂商实现依赖这些接口，SDK 类型及异常在适配器内转换。手机与手表之间仅传协议字段。设置页通过用例读取可用选项，避免散落型号判断。

由 `app` 的 bootstrap 显式注册随包发布的实现，按功能延迟初始化。先检查系统 API 级别、服务和 SDK 版本，再查询能力与授权。厂商名只可用于筛选候选实现。对外区分可用、设备不支持、需要授权和暂时不可用；授权、连接或服务变化时重查。实验开关控制用户是否启用，能力检查决定设备能否执行。避免启动录音时顺带连接手机或健康服务。

优先在现有模块按功能拆包。有独立 SDK、Manifest 组件或分发约束时，再抽为可选 Android Library，由构建配置决定是否包含。通用构建应能在没有三星 AAR 的环境中编译。已有应用 ID、设置和片段格式在迁移中保持兼容。

### 迁移与验收

1. 先隔离现有 Data Layer 调用与服务入口，保留现有传输协议；验证无 Google 服务时可冷启动、录音、暂停和恢复，有 Google 服务时双端校验和回执仍通过。
2. 再整理音频能力和诊断结果。用替身覆盖权限拒绝、空计数器和服务中途失联；在真机验证记录的实际编码配置及分段可解码。
3. 有明确产品需求时接入首个厂商适配器。验证通用构建可独立编译，且使用同一套用例测试。兼容性记录按型号、固件和能力分别标注。设备矩阵至少覆盖现有 Watch5、另一品牌 Wear OS 和可安装 APK 的无 Google 服务 Android 手表；模拟器补充异常路径，长时录音与离电续航以真机为准。

## 参考与取舍

- [Now in Android](https://github.com/android/nowinandroid)：参考模块边界和平台依赖隔离，并非直接照搬其结构。
- [Android Showcase](https://github.com/igorwojda/android-showcase)：参考按功能组织和依赖方向。
- [Kotlin DDD 示例](https://github.com/ttulka/ddd-example-ecommerce-kotlin)：参考聚合及应用用例的职责分离，不引入服务端框架。

当前没有跨域事务、消息总线和云端同步需求，因此不引入相关抽象。编码器与 Android 生命周期仍需实机验收，模块测试不能代替录音质量及耗电测量。
