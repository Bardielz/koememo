# 从全天腕录到可核对文字稿

2026-11-28 设计提案。目标用户早上在手表点一次开始，离开手机仍能记录，晚上在手机上找到一段对话，点一句文字就能听回当时的声音。首个验收组合是 Galaxy Watch5 44 mm 和一加 12，目标是覆盖 8～12 小时日常佩戴。其他可安装应用的 Android 手表按能力逐项验收。

## 从结果倒推

| 用户需要的结果 | 做错的代价 | 谁负责、何时做 |
| --- | --- | --- |
| 说过的话有机会被找回 | 漏掉一句轻声后，换模型也无法恢复 | 手表在用户开启的会话中连续采集，先保留可解码原音。低电量停机、失帧、手动暂停和实验性省略各有记录。 |
| 手机断连半天，录音仍完整 | 把传输成功当成保存成功会丢失唯一副本 | 手表本地关段，手机持久化且校验后回执。两端能重启，重传可去重。 |
| 找到一句话就能回听 | 静音省略后，播放器的第十分钟可能已不是现实中的第十分钟 | 保留会话、采集轮次、分段身份和采集到文件的时间映射。手表标记、文字、传感器和摘要使用同一来源。 |
| 得到可修订的多语文字稿 | 错误语种、远讲漏词或 AI 补写会改变原意 | 手机离线解码和转写。用户可听原音、纠正文字、保留修订；增强、分人和总结可以稍后重算。 |
| 今天录得够久，晚上处理得完 | 在腕上做推理会与采集争夺电量；把所有处理推迟也可能积压 | 手表以有效录音时长和漏录衡量，手机以定稿耗时、准确率和队列积压衡量，PC 作为可选批处理端。 |

以默认 AAC 48 kb/s 估算，8～12 小时产生约 **173～259 MB** 编码负载，忽略封装开销。16 kHz、16 位、单声道的连续 PCM 则约为 **0.92～1.38 GB**。这支持手表存编码原音、手机按窗解码的分工。容量算术能给出传输和空间预算；省多少电仍须离电对照。

## 最小可交付的闭环

**手表手动开始 → 本地关段 → 手机校验入库 → 离线转写 → 点句回听。** 标记和同步恢复都不触发麦克风。每一步独立显示状态，用户可以在手机模型尚未就绪时先听录音。

1. **采集与时间。** 沿用录音用例和存储适配器。每轮采集携带单调时钟锚点、采样率、采集样本位置及经过时间的显示锚点。手动继续产生新轮次，重启后新建时钟锚点。将实际保留的区间映射到文件内可解码位置，扣除静音省略，恢复时补回的样本只计一次。系统中断和来源不明的空档单独标出。举例说，标记落在一段被省略的静音中央时，应显示“此处无音频”，可跳前后保留片段。指向下一段音频的按钮应明确说明跳到了哪里。
2. **传输与保管。** 在现有 `packages/contracts/audio` 增加可协商的版本化分段清单，沿用 `会话 + 文件名` 的来源身份，带上轮次、序号、编码配置、内容哈希和映射版本。哈希校验内容，同一内容在不同时间出现时仍保存两个来源位置。保留旧协议的字段布局；支持新能力的对端另行交换清单。音频完成校验并持久化后才能回执；清单缺失时仍可播放，绝对定位标作未知，后到可补。手表副本的删除由独立保留策略或显式操作决定。
3. **转写与修订。** 在手机端，转写从已校验文件建任务。以内容哈希、模型版本、预处理/切窗配置为计算键，结果经来源映射归入会话。PR #25 的固定窗是可回放的比较基线。随后试音量归一、VAD 留边和重叠去重，保留低电平原音；一次只改变一个因素。保存区间结果和进度后再更新界面。模型重算生成新版本，人工修改保留。只有语句级定位时，界面按句回听。
4. **发言人与总结。** 在同一时间轴上记录“谁在何时说”，允许多人重叠与未知身份。人声降噪、分离同时讲话的人、按声音区分说话人是三项独立能力。默认先在原音上做 ASR 和分人，再按时间重叠关联；分离后的音轨作为可丢弃的派生输入。手动确认过的发言人名称随文字稿保存。摘要中的行动、责任人和结论引用文字稿版本与原音区间，原稿修订后提示摘要待更新。没有来源支持的字段留空。
5. **设备适配。** 各用例只依赖所需原子能力，已有 `CaptureBackends`、`TransferChannel` 和诊断端口继续使用。标准 Android 实现优先；在使用点检查 SDK、权限、编解码器初始化和固件能力。没有 Google 服务的手表保留本地录音与导出路径。新开传感器、厂商加速、USB/BLE 传输适配器都要能独立失败。手机、桌面共享清单与结果格式，平台 API 保留在各自适配层。

### 哪些实验会改变产品决定

- **手表省电。** 静音门控会减少部分编码、写盘和传输，采集仍在工作；它还可能不可逆地漏掉轻声。完整留存继续作为默认。硬件编码、GPU、DSP 或 Rust 均以相同音频质量和有效覆盖下的整机离电收益决定去留。双端性能统计由实验总开关控制，按任务记录耗时、温度、电量和采样范围，正文和原音排除在诊断日志之外。
- **语种与模型。** Mac 的四语小样本支持 SenseVoice 作普通话快速基线，Fun-ASR-MLT 作多语候选，Qwen 保留为中英切换对照。Gemma 可以接收音频，但短前缀、纯噪声和切换语种都可能得到高风险结果。默认采用多语转写；若启用语种探测，先找到含讲话区间，跨窗一致才提供可撤销的提示。模型自报标签不充当置信度。最终选择以手机实测及人工腕录参考为准。
- **摘要、传感器与 PC。** Gemma 优先尝试从有时间戳的文字稿生成带引用摘要。心率与运动是可选上下文，附采集时间、缺测及离腕质量标记，区别于说话人和情绪标签。PC 首先提供批量复核、评测和导出；需要更大模型时再增加离线重算。实时无线传音作为独立产品功能评估，日常记录优先已关段同步。

## 实施顺序与验收

| 顺序 | 最小变更 | 验收与停止条件 |
| --- | --- | --- |
| P0 · 音频完整性与续航基线 | 复用现有导出和审计。固定默认音源、采样率、编码，记录屏幕、无线、充电状态及实际开始/结束原因。准备跨段、摘表、轻声、断连、来电及用户暂停样例。 | Watch5 拔电先跑 8 小时，再挑战 12 小时；列出用户期望录制时间、已知省略、已知中断、未解释缺口、可解码时长和剩余电量。未解释缺口逐个追踪。与相同条件的纯待机对照，充电长跑仅验证稳定性。 |
| P0 · 时间映射和交付 | 先做一份跨两个文件、一次静音省略及一次人工标记的清单样例，贯通手表、传输、手机播放器。补旧录音和旧客户端兼容。 | 在断连、半文件、重复回执、杀进程后重复同步，已验文件逐个 SHA-256 一致，逻辑来源不重复。关闭静音、开启静音、跨段、暂停继续四种回听都能落到对应原音。旧录音的缺失元数据不伪造。 |
| P1 · 可复核文字稿 | 独立验收 PR #25 的手机转写，先保留手动触发与现有进度格式；增加会话级列表和来源定位，再引入持久任务及检索、校订、导出。实验传感器与人声门控分开验收。 | 手机离线处理一个真实工作日的积压，关屏、切后台及杀进程后可继续，手动暂停仍有效。记录完成时间、峰值内存、掉电与热降频。按普通话/英语/混说统计 CER、WER、整句漏识别、静音误出字；用人工标注的起止点报告回听偏差。 |
| P2 · 分人与有来源的摘要 | 对多人片段先标匿名发言人，再增加重叠处理、手动改名和带引用摘要。PC 可复用相同结果格式。 | 人工参考含双人轮换与重叠说话，记录说话人分段错误率、错归人和漏分。逐条点摘要回听；疑问变断言、错认责任人、无来源行动项都计作错误。转写或摘要失败仍可播放和导出原音。 |

建议先标注 30～60 分钟获准使用的腕录，覆盖安静近讲、自然垂腕、街噪、多人重叠和中英切换，并留出独立验收集。标准朗读集用于跨版本回归，对同一份干净输入叠加固定信噪比噪声可定位退化原因；真实腕录决定是否值得发布。跨机型至少分别验证 Watch5、另一品牌 Wear OS 和无 Google 服务的可安装 APK 手表，按能力公布结果。

## 落地进度与下一次验收

PR #27 已打通会话时间映射、标记、传感器摘要和按窗口回听。本轮将手机日常入口调整为会话，复用旧转写进度，加入持久调度、跨片段查找和来源绑定的校订。手机同时保存最近一次收到的手表文件清单，能区分尚待同步的文件、缺少时间轴的旧录音和已知省略的静音。

下一次验收在 Watch5 与一加 12 上完成整个工作日的回放。先做同条件离电对照，再用手机处理同一天的积压；记录首段可读时间、全场完成时间、手机温度、电量，以及人工抽查的漏词和回听偏差。摘要、匿名说话人和备选 ASR 模型使用同一组有人工参考的区间评估。
