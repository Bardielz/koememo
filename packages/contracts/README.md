# 录音传输协议 v1

手机向声明 koememo_audio_v1 能力的手表打开 /koememo/audio/v1 全双工通道。两端共享 audio/src 的字段校验和序列化。整数使用 Java DataStream 大端编码，字符串使用 writeUTF/readUTF。

手表发送清单条数及不可变片段的会话、文件名、字节数和 SHA-256。手机逐个发送清单下标与已接收偏移，手表返回剩余字节。手机验证落盘文件后回传哈希，手表持久化接收确认。已存在且校验一致的文件只交换确认。手机以 -1 结束，手表返回 true。断线后重新获取清单；索引仅在单次连接内有效。协议不兼容变更应启用新路径和能力名。

支持 koememo_audio_sessions 的手表同时接受 /koememo/audio/v1/{UUID}。手机为每次用户发起的同步生成 UUID，重试沿用该值，便于按会话关联两端 KoeMemoSync 日志。旧版使用原路径和相同的音频协议。

支持 `koememo_audio_timeline_v1` 的手表接受 `/koememo/audio/v1/timeline-v1/{UUID}`，沿用音频分段与回执协议。手机发送 -1 后，手表写入会话数量（int），每个会话依序写入 ID 和经字段筛选的时间轴 JSON 行（writeUTF）。空串结束该会话，随后是 32 字节 SHA-256，按每行 UTF-8 加 LF 计算。手机验证后原子替换会话文件，全部完成时回复 true，手表返回最终确认。重试可复用已验证音频并重新取得完整时间轴。原始心率、加速度以及诊断日志仅保存在手表端。

支持 `koememo_audio_context_v1` 的手机与手表通过 `/koememo/audio/v1/context-v1/{UUID}` 交换带传感器摘要的时间轴，沿用上述确认和原子替换流程。兼容旧路径时继续发送原时间轴。每条 `audio_context` 绑定 run、文件名、SHA-256 和片段内 15 秒窗的起点。为已启用传感器且有音频时钟的录音生成清单内已关闭片段的窗口。仅计入能定位到对应音频的样本，空窗报告零条。随每窗发送运动样本数、平均 ENMO（m/s²）、心率总样本数、有效样本数、有效 BPM 最小/最大值及有有效读数的秒格数。一个秒格内多次有效回调只算一个有读数的秒格；末窗不足一秒的尾部算一个秒格。`timeline_progress` 仅保持长扫描时的连接。重复同步会替换快照。
